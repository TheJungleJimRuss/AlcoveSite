# 0007: Cassette A/B uses a Blender GLB rendered by three.js, with an SVG fallback

Status: accepted (2026-11-16); spike `.agents/issues/cassette-ab/spike/index.html`, ticket `cassette-ab/issues/01-approach-spike.md`

The Cassette A/B deck (spec `.agents/issues/cassette-ab/spec.md`) needs a cassette that flips in 3D, with reels that spin and a tape pack that moves from the left reel to the right. A flat SVG cassette cannot turn over convincingly.

**Decision:** model the cassette in Blender, export one GLB, and show it with three.js on a canvas inside the deck. Keys, meters, counter and J-card stay HTML. When WebGL is unavailable, the GLB fails to load, or `prefers-reduced-motion` is set, show the existing SVG cassette (the prototype drawing) instead, so nothing depends on the 3D path.

- **Dependency:** three.js 0.187.0 (MIT), vendored unmodified under `vendor/three/` (`build/three.module.js`, `build/three.core.js`, `examples/jsm/loaders/GLTFLoader.js`, `examples/jsm/utils/{BufferGeometryUtils,SkeletonUtils}.js`). Loaded through an import map (`three`, `three/addons/`); no build step. Cost: about 2.1 MB uncompressed, about 420 KB gzipped (core 292 KB + module 130 KB; the loader is small), loaded only on Work and only when the deck is near the viewport (dynamic `import()`), never on the other pages. The files are not minified; a minified, tree-shaken bundle would be much smaller but needs a build step, so it is a later option, not part of this decision.
- **Model:** `models/cassette.glb`, 72 KB (11.5 KB gzipped), about 2,000 triangles, no embedded images. Source script `assets-src/cassette/build_cassette.py` (run headless: `/Applications/Blender.app/Contents/MacOS/Blender --background --python assets-src/cassette/build_cassette.py`) and `assets-src/cassette/cassette.blend`. Modelled from scratch, so there is no third-party licence. Matte materials only (roughness 0.45 to 0.9).
- **Label text:** the label meshes carry no baked text. three.js draws each side to a 2D canvas (stripe, side letter, title, handwritten note) and uses it as the map, so the words can come from the `data-edit-key` text and Admin Edit mode keeps working, and the colours come from palette tokens.
- **Light:** one hemisphere light and two directional lights, tinted from CSS custom properties (read with `getComputedStyle`), re-read on a colour scheme change.
- **Rejected:** pre-rendered Blender stills + CSS 3D (cheaper, but the flip would be a card flip between two flat images, with no live reel or pack changes); CSS 3D transforms on the SVG (no real depth, the window and hubs stay flat).

**Result (2026-11-16):** the page loads, renders both sides, flips (180 degrees about the vertical axis, 0.7 s, small lift toward the camera and back), spins the reels and scales the packs, with zero console errors at phone width (375 px) and no horizontal overflow. The page reported 60 fps in the desktop browser pane. A phone-class device has NOT been measured; with about 2,000 triangles and three lights this should be well within budget, but ticket 03 must check on a real phone and keep the pixel ratio cap of 2 (lower it if frames drop). The no-WebGL path was exercised with `?nogl` on the spike page.

**Consequences:**
- Reels spin about the node's local Z axis, packs scale in local X and Y only (the pack axis is Z); the integration must not scale Z.
- The shell has a real see-through window, so the deck well behind it should stay dark.
- A canvas label texture must be redrawn when the side text or the palette changes.
- Tests that need rendered frames in a hidden tab must step the animation by hand: browsers throttle `requestAnimationFrame` there.
- The three.js files add about 2.2 MB to the repo. Replacing them later with a minified build is a file swap.

**Amendment (2026-11-16, ticket 07): the whole player is the model.** The 3D scene is now a top-loading portable cassette player (reference only, nothing copied: Sony TC-D5M / Panasonic RQ-series style) with the cassette seated in its bay under a hinged clear door. `models/cassette-player.glb` (about 230 KB, about 6,100 triangles; source `assets-src/cassette-player/build_player.py` + `.blend`; it contains the same cassette code, nodes `reelL/reelR/packL/packR/sideA/sideB` unchanged, plus `cassette`, `door`, `keyPlay/keyPause/keyStop/keyFlip`) replaces `models/cassette.glb` (deleted). `cassette-3d.js` frames the whole player (camera 52 degrees above the front, one shadow-casting key light), latches the Play key down while playing, and drives the Flip from `ab:flip-start` as eject, lift, flip, insert: the door swings up, the tape rises, turns end over end then a half turn flat (so the head edge ends up at the front), drops in, the door closes. `ab-compare.js` flip timing is now 700 + 700 ms. The VU meters (`vu-meters.js`, both dials) and the on-page scrubber are removed; the page keys are icon-only (inline SVG, `aria-label`); `__abDeck.seek` remains for tests. The SVG fallback is now a simple player drawing. Still matte (ADR 0001); the door glass is the only transparent material.

**Amendment (2026-11-16, ticket 08): textures, plan view, standalone.** The player is textured (procedural brushed shell, rubber grain, tape-pack winding, real speaker cuts; GLB about 540 KB) and drawn from straight above with a 14 degree field of view, with no panel, frame or reserved space: the transparent canvas sits on the page's brushed-metal surface with a soft contact shadow. ADR 0001's matte rule is relaxed for the shell only: satin metal (metalness 0.7, roughness >= 0.45, small procedural environment map); everything else stays rough dielectric. A tape ribbon joins the packs and is recomputed from the pack radii (`cassette-3d.js`, SVG twin in `ab-compare.js`); the cassette is seated on the spindles with an inner back wall, flanges and guide posts. Flip is a roll about the front-back axis with a lift toward the camera.

## Amendment (ticket 09)
The transport keys are the keys drawn on the player. Transparent `<button>`s overlay them (projected from the 3D model, fixed positions over the SVG fallback), so there is no separate key row and accessibility is unchanged.

## Amendment (2026-11-18): images instead of three.js
User: simplify the deck, the cassette need not open, make it lighter, "use images instead of a three.js render like the record player", and render the door animation in Blender. The deck is now stacked top-down Cycles renders of the same Blender model (`assets-src/cassette-player/render_layers.py` -> `images/cassette/`): deck, two tape packs (CSS `scale`), two reels (CSS `rotate`), cassette shell, and a 10-frame door strip (`ONLY=door`, stitched by `scripts/make-door-sheet.mjs`; glass alpha is snapped to flat steps, 2x sheet 118 KB). The label is HTML on a blank rendered label. Flip = the door swings open through its frames (`translate` on the strip, steps), the side changes, the door closes; the cassette no longer turns over. three.js, `cassette-3d.js`, the GLB, the import map and the SVG fallback were deleted (no fallback is needed: images work without WebGL, in Lite mode and under reduced motion, where the flip is instant). The event contract and `window.__abDeck` are unchanged. Result at 20x CPU throttle: play/flip p95 33 ms -> 17 ms, no 2D canvas work.
